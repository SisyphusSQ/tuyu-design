# LibTV 调研报告

调研日期：2026-05-16  
调研范围：LibTV 使用指南、LibTV Skill 使用指南、空白画布、公开案例「夏日探索图鉴」  
调研方式：使用已登录 Chrome 页面观察与低风险交互；未执行生成、上传、复制项目、授权、会员或任何可能消耗积分的操作。

## 1. 结论摘要

LibTV 的核心不是传统多页面工具，而是一个以无限画布为主入口的 AI 视频创作系统。它把文本、图片、视频、音频、脚本、素材、模板、生成结果和 Agent 能力都放进同一个可缩放、可连线、可组织的画布里。

如果图屿 Studio 参考 LibTV，产品定位应从“本地影视前期制作与生成交接工作台”升级为：

> 私有化 AI 视频创作画布：以本地项目、资产连续性、节点工作流、可审计运行和结果评审为核心，提供可定制、可迁移、可恢复的创作生产系统。

这意味着设计文档需要调整产品模型，Pencil 设计稿也需要从页面集合改为 canvas-first 的真实应用设计。

## 3. LibTV 产品结构

### 3.1 主界面是无限画布

LibTV 的空白项目打开后直接进入深色无限画布。画布背景为点阵网格，中心提供“自由生成节点”的起始提示，并给出几个高频入口：

- 故事脚本生成
- 角色三视图
- 首帧图生视频
- 音频生视频

画布不是一个展示层，而是生产主场。用户在画布上创建节点、组织素材、查看历史、插入模板、连接节点、执行生成、回收结果。

### 3.2 画布布局

观察到的主要区域：

| 区域 | 功能 |
| --- | --- |
| 顶部栏 | 项目名称、LibTV Skills、保存画布、分享、通知、会员/积分、个人入口 |
| 左侧工具栏 | 添加节点、打开工具箱、我的素材、历史记录、教程、联系客服 |
| 画布中心 | 无限空间、节点卡片、分组、连线、案例制作过程 |
| 左下控制 | 整理画布、小地图、网格吸附、缩放比例、放大/缩小 |
| 弹出面板 | 节点菜单、工具箱、素材库、历史记录、快捷键 |

### 3.3 节点菜单

点击“添加节点”后，节点入口分成两类：

基础节点：

- 文本：剧本、广告词、品牌文案
- 图片：海报、分镜、角色设计
- 视频：创意广告、动画、电影
- 视频合成：多个视频片段合成
- 音频：音效、配音、音乐
- 脚本：创意脚本、生成故事板

资源入口：

- 上传：图片、视频、音频文件
- 从图库选择：从历史生成中选择素材

这里的“节点”既是内容载体，也是任务入口。它不是纯领域对象，也不是纯 UI 卡片，而是创作过程中的可执行单元。

### 3.4 工具箱与模板

工具箱里出现大量预设模板和镜头运动类能力，例如：

- 左弧滑行、右弧滑行
- 商品震撼登场
- 360 旋转展示
- 机械臂视角
- Live 2D
- 瞳孔拉近
- 破盒而出
- 反重力漂浮
- 粒子融解
- 旅拍转场
- 英雄视角
- 大师分镜九宫格
- AI 室内装修效果预览

这说明 LibTV 的画布不只是“从零搭节点”，还鼓励用户通过预设快速构建可运行生产结构。对图屿 Studio 来说，这对应“项目模板 / 分镜模板 / 镜头语言模板 / 风格模板 / 私有技能包”。

### 3.5 素材与历史

空白画布的素材面板包含：

- 我的素材
- 我的主体库
- 全部、人物、场景、物品、风格、音效、其他

历史面板包含：

- 图片历史
- 视频历史
- 音频历史
- 批量操作

这和图屿现有的资产库、人物/场景/道具连续性、结果回收高度相关。但 LibTV 的入口更贴近画布操作：素材和历史不是独立页面，而是随时从画布侧边呼出。

### 3.6 快捷键与画布操作

观察到的快捷键能力包括：

- 成组、解组、合并分镜组
- 连线
- 复制整组
- 生成
- 新建节点
- 节点复制
- 创建副本
- 放大、缩小、适应画布
- 移动画布
- 整理画布
- 撤销、重做、删除

这些能力说明画布是长期操作界面，需要完整的生产级交互，而不是展示图谱。

## 4. 案例页观察

案例「夏日探索图鉴」由展示页和制作过程组成。

展示页提供：

- 成片封面/预览
- 立即观看
- 查看制作过程
- 更新时间
- 作者信息
- 横向案例推荐

点击“查看制作过程”后进入只读画布。画布顶部提示“只读模式，如需创建请点击复制项目”，并提供“复制项目”入口。画布内部包含大量文本、图片、视频节点，节点之间通过曲线连接，形成从策划、角色/参考图、分镜、图像结果、视频结果到结尾输出的生产链。

这个模式有两个关键启发：

1. 案例不是静态作品展示，而是可复用工作流。
2. 制作过程本身是产品资产，可以被复制、学习、改造。

图屿 Studio 如果做私有化定制版本，可以把“案例工程”设计为本地项目模板：用户可以保存自己的成熟链路，团队或个人反复复用，而不是每次从空白画布开始。

## 5. Skill / Agent 入口观察

LibTV Skill 指南体现了另一个产品入口：用户可以通过 OpenClaw、飞书插件、KimiClaw 等 Agent 环境调用 LibTV。其流程大致是：

1. 安装 Agent/Skill 环境。
2. 获取并安装 libtv-skills。
3. 配置 LibTV access key。
4. 在 Agent 中发起创作任务。
5. 任务在 LibTV 中创建项目、运行节点、生成结果。

指南和评论中反复出现的问题包括：

- access key 配置失败
- Agent 上传图片后 LibTV 无法识别
- 节点没有正确落到画布
- 生成慢或排队时间长
- 积分消耗不可预期
- 失败后积分/结果处理不清晰
- 缺少取消/停止入口
- 模型选择不可控
- 画布里结果或历史不可见

这些问题对图屿 Studio 很有价值。私有化产品不应该只模仿 LibTV 的画布形态，更要把它的风险点做成明确设计：

- 外发前确认
- 成本/配额预估
- 运行中可取消
- 每个节点有运行日志和 attempt history
- 失败有错误语义和可恢复动作
- 结果必须回到画布和本地项目
- Provider 凭据隔离
- 本地路径和上传引用有清晰边界

## 6. 对图屿 Studio 的产品启发

### 6.1 需要调整的定位

当前图屿 Studio 的设计文档已经具备本地项目、Creative Graph、资产连续性、运行时、交接包和评审闭环。这些基础不需要推翻。

但如果参考 LibTV，主产品不应再被描述成“生成交接工作台”。更合适的表达是：

> 图屿 Studio 是面向个人/小团队的私有 AI 视频创作画布，把剧本、角色、场景、参考资产、分镜、提示词、生成任务、结果评审和交接包组织在一个本地可追溯项目中。

### 6.2 Creative Graph 需要从数据图谱升级为生产画布

现有 Creative Graph 偏向表达领域关系：Script、Character、Scene、Shot、Prompt、Package、Result。

参考 LibTV 后，它还应该承载实际生产节点：

- 文本节点
- 图片节点
- 视频节点
- 音频节点
- 脚本节点
- 上传/外部引用节点
- 工具/模板节点
- 生成任务节点
- 结果节点
- 分组/Frame 节点

领域对象仍然是底层真相，但画布节点应该允许更贴近创作过程的组合方式。

### 6.3 Package Export 不应是主路径中心

图屿原设计里，Package Export 是明确主阶段。参考 LibTV 后，Package Export 更适合作为：

- 外部生成 fallback
- 可审计 handoff
- 运行失败或 provider 不可用时的导出路径
- 需要人工交付时的归档包

主路径应优先是画布上的节点运行、结果回流和评审。

### 6.4 模板体系应该前置

LibTV 的工具箱说明模板是核心体验。图屿应建立自己的模板类型：

- 剧本到分镜模板
- 角色三视图模板
- 场景参考模板
- 道具/产品展示模板
- 多镜头连贯分镜模板
- 首帧图生视频模板
- 结果评审模板
- 生产交接模板

模板不只是 UI 组件，而应包含节点结构、输入要求、输出契约、运行能力要求和恢复语义。

### 6.5 私有化差异点

图屿不应该只做一个“LibTV 风格 UI”。它的差异应放在私有化与生产可靠性：

- 本地项目目录可迁移
- 资产 digest 与来源追踪
- 人物/场景/道具连续性锁定
- ProviderProfile 可替换
- 网络与外发默认可控
- 凭据不进入项目文件
- 每次运行有 audit、events、attempt
- 结果评审不覆盖历史
- 支持手动交接和自动运行两条路径

## 8. 对 app.pen 设计稿的影响

当前 `app.pen` 如果要贴近后续真实 Studio，应大改为 canvas-first 结构。

建议新的主视觉方向：

- 第一屏就是项目无限画布，不做总览页或文档页。
- 深色画布作为主创作模式，浅色模式作为办公/评审模式。
- 左侧竖向工具栏：节点、模板、素材、历史、搜索、设置。
- 中间画布：真实节点链路、曲线连线、Frame/Group、运行状态、错误状态、结果缩略图。
- 右侧 Inspector：选中节点属性、输入/输出、Provider、运行历史、错误与恢复。
- 底部状态条：缩放、小地图、队列、健康、外发/成本提示。
- 案例/模板浏览：支持“查看制作过程”和“复制为本地项目模板”的设计稿。
- Package Export 和 Result Review 以画布阶段、抽屉或节点详情承载，而不是独立页面主导。

## 9. 后续讨论问题

进入设计文档调整前，建议先确认这些问题：

1. 图屿 Studio 是否把“自动节点运行”作为第一版目标，还是第一版仍以可视化组织 + 手动交接为主？
2. 私有化版本是否允许接入在线 provider？如果允许，默认网络策略和外发确认如何设计？
3. 模板体系第一版是内置模板，还是允许项目级自定义模板？
4. Creative Graph 的底层领域对象是否继续保持严格结构化，画布媒体节点作为展示/任务层？
5. 是否需要设计“案例工程 / 项目模板库”，用于复用成熟工作流？
6. Light/Dark 模式是否都完整支持画布，还是 Dark 为创作主模式、Light 为评审主模式？

## 10. 建议下一步

建议先做一版设计文档调整提案，范围控制在产品模型和画布主路径：

1. 重写产品定位和边界。
2. 定义 canvas-first 信息架构。
3. 扩展节点类型和节点运行模型。
4. 调整用户工作流和验收标准。
5. 之后再基于新模型重画 `app.pen`。

这样可以避免只在视觉上模仿 LibTV，而没有把图屿自己的私有化、本地闭环、连续性和审计能力沉淀到产品设计里。
